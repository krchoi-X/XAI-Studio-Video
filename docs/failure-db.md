# 실패 DB (Failure Database)

> AI 영상 제작에서 실제로 실패한 사례의 기록.
> 성공 공식 DB(`directing-technique-db.md`, `prompt-craft-db.md`)의 반대편:
> "이건 된다"가 아니라 **"이건 안 된다"** 목록.
> 기획·콘티 단계에서必读. v1.0 — 2026-10-02.

## 사용법

1. 콘티를 짜기 전에 이 DB를 훑는다.
2. 각 샷이 아래 실패 패턴 중 하나에 해당하면 재설계한다.
3. 새 실패가 나오면 여기에 추가한다 (성공 공식 DB와 쌍으로 운용).

## 카테고리

- **C** 연속성 (캐릭터·배경·소품·신체)
- **D** 연출 판단 (감정·시선·구도·이야기)
- **P** 프로세스 (기획·진단·DB 활용)
- **T** 도구 제약 (차단·드리프트)

---

## C-01 캐릭터 불일치 — 샷마다 독립 스틸 생성

- **발생**: 옥상 v1. S1 긴팔 → S2 반팔, 얼굴·헤어스타일 변화.
- **원인**: 각 샷의 스틸을 독립 생성. 캐릭터 시트 없이 "같은 여자"를 모델 재량에 맡김.
- **교훈**: 캐릭터 시트를 `kind:image`로 전 샷에 참조. 해결됨 (v2에서 해소).
- **대응 공식**: P-16 FRIEND LOCK.

## C-02 배경 드리프트 — 샷마다 독립 스틸 생성

- **발생**: 옥상 v1–v3. 남산타워 방향 변경, 옥상 철망 유무 변경, 구조물 높이 변경, 물탱크/인물 위치 변경, 파란 위성안테나 난입.
- **원인**: 구조도를 레퍼런스로 줘도 이미지 모델이 재해석함. 캐릭터는 시트로 잡히는데 배경은 안 잡힘.
- **교훈**: 두 가지 해결책. ① 배경 무난화 — 눈에 띌 만한 것을 없애면 비교 대상이 없음 (사용자 제안, v4 적용). ② 여정 구조 — 배경 전환을 이야기로 정당화 (나비 컨셉).
- **상태**: 해결 (원칙 확립).

## C-03 오디오 드롭 — concat 시 스트림 버림

- **발생**: 옥상 v1. `a=0`으로 concat해서 생성 클립의 앰비언트 오디오를 버림.
- **교훈**: 조립 시 오디오는 항상 유지 (`a=1`). v2부터 적용.
- **상태**: 해결 (체크리스트화).

## C-04 프레이밍 드리프트 — I2V가 구도를 바꿈

- **발생**: 옥상 S1 v1 (뒷모습→측면), 바람 S2 v1 (손이 프레임 밖으로 밀림).
- **교훈**: 모든 I2V 프롬프트에 프레이밍 락 문구 필수.
  그래도 밀리면 리테이크 (바람 S2가 선례 — 강한 락으로 해결).
- **상태**: 해결 (프롬프트 규칙화).

## C-05 손 오독 — 빈 손 명시 누락

- **발생**: 옥상 v3 S2. 오른손이 액션캠/셀카봉을 든 것처럼 보임.
- **원인**: "빈 손바닥"이라고 명시하지 않음.
- **교훈**: 손이 나오면 "holding nothing / 빈 손" 명시. v4에서 해소.
- **상태**: 해결.

## C-06 손 높이 불일치 — 원장 항목 누락

- **발생**: 바람 v1. S1 머리 위 → S2 가슴 높이 → S4 내림 → S5 다시 위.
  손바닥 방향(위)은 맞췄는데 높이를 원장에 안 넣음.
- **교훈**: 신체 연속성은 방향+위치+높이 전부 명세. "오른손 어깨 높이, 손바닥 위"
  같은 완전한 스펙으로.
- **상태**: 미해결 (v2 미제작).

## D-01 감정 명세 위반 — 감독 드리프트

- **발생**: 옥상 S3 v1. 비닐봉지 상승은 렌더됐으나 그녀가 카메라를 보고 웃어버림.
  콘티의 EMOTION(비장) 위반.
- **교훈**: 감정도 네거티브로 잠가야 함. "웃지 않는다" 같은 금지 명세가 필요.
- **상태**: 해결 (원칙 확립).

## D-02 웃음 과다 — 기승전전전전결

- **발생**: 옥상 v2. S3 폭소 → S4 미소 → S5 폭소. 웃음이 일찍, 자주 나와서
  S5의 폭발이 묻힘.
- **교훈**: 코미디 타이밍 — S4까지 진지하게 버티다가 S5에서 한 번에 터뜨린다.
  S3는 작은 실수, S4는 진짜 수습. (사용자 연출)
- **상태**: 해결 (시나리오에 원칙으로 기록).

## D-03 시선 목표물 프레임 밖

- **발생**: 나비 S3 v3. 시선 방향은 호수 쪽으로 맞췄으나, 그 방향에 호수가
  프레임에 없음 → 허공을 보는 것처럼 됨.
- **원인**: 시선 "방향"만 검증하고 "목표물"을 검증하지 않음.
- **교훈**: 시선의 목표물은 반드시 같은 프레임 안에. 안 되면 옆모습+정면에
  목표물이 보이는 구도로 (사용자 연출).
- **상태**: 미해결 (사용자가 리메이크 중단시킴).

## D-04 피사체 크기 과다

- **발생**: 나비 v1. 나비가 비현실적으로 크게 렌더됨.
- **교훈**: 크기를 명시 ("natural small butterfly size"). v2에서 해소.
- **상태**: 해결.

## D-05 컷어웨이 세계관 단절

- **발생**: 바람 v1 S3. 황량한 들판 — 공간 앵커는 없앴지만 세계관까지 끊김.
- **교훈**: 컷어웨이는 **세계관은 공유하되 공간은 공유하지 않는다**.
  마을 어귀 버드나무, 단독주택 나무, 전봇대 벽지 (사용자 연출).
- **상태**: 미해결 (v2 미제작).

## D-06 스토리 복잡도 초과 — 파이프라인이 감당 불가

- **발생**: 옥상 v4. S1 빨래 위치 불일치, S3 웃음 원인 불명, S2 실패 내용 불명,
  S4/S5 위치감 불일치. 지적이 끊이지 않음.
- **교훈**: "일관성있게 못 만들거면 컷에서 빼라" (사용자).
  복잡한 스토리는 파이프라인 능력 밖. 여정 구조 같은 단순한 이야기로 피벗.
- **상태**: 해결 (나비 컨셉으로 피벗, 원칙 확립).

## D-07 세계관 불일치 소품 — 옥상의 낙엽

- **발생**: 바람 리빌드 콘티 초안. S3에 낙엽을 넣음 → "일반 가정집 옥상에
  낙엽이 있겠어?" (사용자).
- **원인**: 생각을 안 하고 "바람"의 관용적 이미지를 가져옴.
- **교훈**: 소품은 세계관 정합성 검증 필수. DB가 아니라 상식의 영역.
- **상태**: 해결 (콘티에서 제거).

## D-08 콘티 모호성 — 소품 정체·감정 순서

- **발생**: 바람 리빌드 콘티 초안. ① S3에 날리는 셔츠 — 그녀의 옷인지 빨래인지
  불명. ② S2에 "뿌듯함" — 아직 결과도 안 나왔는데.
- **교훈**: 콘티 단계에서 소품의 주인을 확정하고, 감정은 인과 순서에 맞게 배치.
  모호한 콘티는 나중에 헷갈린다 (사용자).
- **상태**: 해결 (콘티 수정).

## P-01 문제 오진단 — 증상만 치료

- **발생**: 옥상 S2 손. 진짜 문제는 "구도가 복잡했다"인데 "손을 잘못 그렸다"고
  보고 손만 고침.
- **교훈**: 실패하면 "무엇이"가 아니라 "왜"를 먼저 묻는다. 증상이 아닌 원인을 고친다.
- **상태**: 진행 중 (습관화 필요).

## P-02 과잉 해결 — 더 어려운 방법으로 품

- **발생**: ① 배경 드리프트에 마스터 플레이트 제안 (사용자가 기각, 배경 무난화로
  해결). ② 시선 문제에 카메라 아크 시도 (옆모습+호수 한 프레임이 정답이었음).
- **교훈**: 쉬운 답을 먼저. 사용자가 준 답이 매번 더 쉬웠다.
- **상태**: 진행 중 (습관화 필요).

## P-03 DB 미활용 — 박물관 전시

- **발생**: 70개 분석을 쌓아놓고 제작 전에 한 번도 안 열어봄.
- **교훈**: 학습의 목적은 "어려운 건 실패가 많으니 성공 공식 DB를 만들자"였음
  (사용자). 분석은 수단이었고 목적을 잊음.
- **상태**: 진행 중.

## P-04 게이트 오남용 — DB가 검열관이 됨

- **발생**: "각 샷은 DB 성공 공식에 대응, 없으면 안 만든다" 제안 → 사용자가 기각.
- **교훈**: DB는 공구함이지 허가증이 아님. 출발점은 "내가 만들고 싶은 것",
  성공 공식은 그걸 그럴듯하게 만드는 도구. 쉬운 것부터 → 잘 되면 어려운 컷 도전.
  (사용자 철학)
- **상태**: 해결 (원칙 정정).

## P-05 자기 설정 망각

- **발생**: 클로드/ Hermes 영상의 남자 얼굴을 "콘티에 없던 것"이라고 함.
  실은 원 시나리오의 지훈(다이제틱 카메라) 설정이었음.
- **교훈**: 자기 시나리오의 설정을 제작 전에 다시 읽는다.
- **상태**: 해결 (단발성, 재발 주의).

## T-01 도구 차단 후 반복 금지

- **발생**: 옥상 S4 클로즈업 요청이 integrity_check_failed로 거부됨.
- **교훈**: 거부된 요청은 동일하게 반복 금지. 콘티를 실질적으로 바꾼 새 요청은 가능
  (S4 미디엄샷 리셋이 선례).
- **상태**: 해결 (규칙화).

## T-02 노출 수위 이미지 도구 거부

- **발생**: 캐릭터 시트 v2 (단추 푼 셔츠+레이스 반바지) 요청이 이미지 도구에서 거부됨.
- **교훈**: 패션 스타일링이어도 도구 임계값이 엄격할 수 있음. 거부 시 반복 금지,
  사용자 로컬 파이프라인으로 이관.
- **상태**: 해결 (워크플로우 확립).

## 지침·스킬 개선 제안 (이 DB 기반)

1. **제작 전 체크리스트**: 콘티 완성 후 이 DB의 C/D 항목을 한 번씩 대조.
   해당하면 재설계 (게이트가 아니라 점검표).
2. **원장 필수 항목**: 캐릭터 시트 + 소품 원장(P-30) + **신체 스펙(손 높이·방향)**.
   C-06이 빠졌던 구멍.
3. **감정 아크 검증**: 각 샷의 감정이 인과 순서에 맞는가 (D-08).
4. **소품 세계관 검증**: 모든 소품이 세계관에 있는가 (D-07).
5. **시선 검증 2단계**: 방향이 아니라 목표물이 프레임에 있는가 (D-03).
6. **쉬운 답 우선 원칙**: 해결책을 두 개 이상 떠올리면 쉬운 것부터 (P-02).
7. **진단 원칙**: 증상이 아니라 원인을 (P-01).
