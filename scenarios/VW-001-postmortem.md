## 2. 네 가지 문제의 원인 분석

### A. 화면비 혼재 — [확인됨] 사실관계

**검증된 사실:**

1. 영상 프롬프트 13회 모두 화면비 미지정 (호출 로그 전수 확인).
2. 결과물: 가로 8개(1248x704), 세로 4개(672x1344: C03·C06·C09·C10),
   이종 1개(C12: 1152x768 = 3:2).
3. 세로 4개는 모두 인물 마스터(1120x2240 세로)를 두 번째 이미지로
   전달한 클립이다. 그러나 같은 조건의 C05·C11은 가로로 나왔다.
4. C12의 3:2는 입력 스틸(밤 오두막, 1920x1280)이 3:2였기 때문에
   그대로 계승된 것이다. ("16:9"를 명시했음에도 이미지 모델이 3:2 출력)
5. 검수 단계에서 키프레임의 **내용**(인물·동작)만 보고 **규격**(치수)을
   한 번도 확인하지 않았다.
6. 조립 단계에서 정규화 없이 `-c copy`로 이어붙였다.

**원인 판정:**

- [추론] 세로 출력의 정확한 트리거는 알 수 없다. 인물 마스터의 세로
  비율이 영향을 줬을 가능성은 있으나(C03·C06·C09·C10),
  C05·C11의 반례 때문에 확정할 수 없다. "세로 참조 이미지 때문"이라는
  단정은 금지한다.
- [확인됨] 확실한 것은 **어느 단계에서도 화면비를 강제·확인하지 않았다**는
  점이다. 프롬프트 미지정 → 검수 미확인 → 조립 미정규화의 3연속 누락.
- 최초 발생 지점: **④ 프롬프트 작성** (비율 파라미터 누락).
  이후 **⑥ 검수**와 **⑦ 편집**에서 두 번 바로잡을 기회가 있었으나
  두 번 다 놓쳤다.

### B. 중세 마을의 미술 설정 — [확인됨] 조사 0건

**검증된 사실:**

1. 제작 전 역사 자료·이미지 레퍼런스 조사를 하지 않았다
   (검색·열람 도구 호출 기록 없음).
2. 스틸 프롬프트는 "medieval European rural village, 14th century,
   thatched-roof stone cottages" 한 줄이 전부였다. 이후의 건축 형태·밀집도·
   재질은 전부 이미지 모델의 사전 분포(prior)에 위임했다.
3. v2의 Open Issues와 Test Plan은 "제작 전에 실제 역사적 복원 자료로
   ... 레퍼런스를 고정"하라고 명시했으나, 베틀뿐 아니라 마을에도
   적용하지 않았다.

**원인 판정:**

- [기억] 판단 당시의 생각: "LH-001에서 스틸 한 줄로 충분한 세계가
  나왔으니 이번에도 되겠지"라는 선례 의존. LH-001의 등대는 단일
  건축물이라 모델 prior가 맞았지만, 마을은 집합 경관이라 prior의
  평균값("원시적·밀집")이 그대로 드러났다.
- [추론] "지나치게 밀집한 원시적 마을"이라는 인상은, 모델이
  "medieval village"를 중세 유럽 농촌이 아니라 판타지·원시 취락의
  혼합 분포로 해석했기 때문으로 추정된다. 검증 불가.
- 최초 발생 지점: **① 자료 조사**. 이후 단계에서 바로잡을 수 없었다 —
  비교할 기준 자체가 없었으므로 검수(⑥)는 작동할 수 없었다.

### C. 우물과 물 긷기 — 연출 선택의 근거 없음

**검증된 사실:**

1. C04 1차 프롬프트는 크랭크를 돌리는 손의 **직접 렌더**를 지시했다.
2. 제작 중 Directing Technique DB를 조회하지 않았다
   (해당 턴의 도구 호출 기록에 DB 읽기 없음).
3. 직접 렌더를 선택한 실제 근거는 [기억] "LH-001 C07(크랭크)가
   됐으니 이번에도 되겠지"라는 선례 의존이었다. 방법론적 검토가 아니었다.
4. 서사상 C04가 전달해야 하는 정보는 "물을 길었다"는 **결과**뿐이다.
   C05(가득 찬 물통)가 그 결과를 보여준다. 작동 과정 자체는
   T-02(결과만 보여주기)로 대체 가능한 비트였다.

**원인 판정:**

- 방법론(T-01 생략 컷 / T-02 결과만 보여주기 / T-08 Never-Render)은
  "어려운 동작을 직접 보여주지 말라"고 이미 말하고 있었다.
  나는 그것을 참조하지 않고, 한 번의 성공 사례(LH-001 C07)를
  일반화하여 직접 렌더를 선택했다.
- [추론] 결과물의 어색함(프레임별 메커니즘 불일치: 크랭크를 돌리는 장면과
  밧줄을 직접 끌어올리는 장면의 혼재)은, 모델이 "손잡이 회전 → 로프 감김 →
  두레박 상승"의 인과 사슬을 일관되게 유지하지 못했기 때문으로 보인다.
  키프레임 2장으로만 확인한 한계가 있어 확정은 불가.
- 최초 발생 지점: **③ 연출기법 선택**. T-02 적용 여부 판단 없이
  선례 하나로 직행했다. ⑥ 검수에서는 신원 문제만 잡고
  메커니즘 일관성은 검사하지 않았다.

### D. 베틀과 직조 — 조사·기법·검수의 3중 누락

**검증된 사실:**

1. 베틀의 실제 구조·직조 동작을 조사하지 않았다 (검색 기록 없음).
   v2가 요구한 "역사 복원 자료로 레퍼런스 고정"을 수행하지 않았다.
2. C08 프롬프트는 **발+손+북+날실**의 3중 협응 동작을 단일 생성에
   요구했다: "Her foot presses a treadle... her hand glides the wooden
   shuttle... she pulls the beater bar."
3. 대안(T-02 인서트: 날실·씨실 교차 클로즈업 + T-05 소리 브리지)을
   제작 중 고려하지 않았다. v2의 Test Plan("먼저 일관된 단일 동작
   클립을 시험")도 지키지 않고 풀 컴포지트로 직행했다.
4. 검수는 키프레임 2장(구도·인물 확인)으로 끝났다.
   **키프레임으로는 동작의 자연스러움을 판단할 수 없다** —
   문제로 지적된 것이 동작의 질감인데, 검사 도구가 동작을 보지 않았다.

**원인 판정:**

- 최초 발생 지점: **① 자료 조사** + **③ 연출기법 선택** (복합).
  ⑥ 검수는 구조적으로 문제를 발견할 수 없는 방식이었다.
- [추론] 모델 한계 추정: 다지(多肢) 협응(발+양손+도구+실의 연동)은
  단일 I2V 생성의 신뢰 구간을 벗어나는 것으로 보인다.
  다만 모델명이 기록에 없어 "이 모델의 한계"라고 단정할 수는 없고,
  "이번 파이프라인에서 관찰된 현상"으로만 기술한다.

## 3. 기존 방법론 활용 여부

| 기법 | 상태 | 근거 |
|---|---|---|
| Directing Technique DB | 알고 있었지만 제작 중 고려하지 않음 | 제작 턴에 DB 읽기 호출 없음 (호출 로그 확인) |
| Prompt Craft DB | 알고 있었지만 제작 중 고려하지 않음 | 상동 |
| T-01 생략 컷 | 알고 있었지만 제작 중 고려하지 않음 | C04·C08에서 적용 검토 기록 없음 |
| T-02 결과만 보여주기 | 알고 있었지만 제작 중 고려하지 않음 | C04(물 긷기 결과=C05에 이미 존재)에 미적용 |
| T-05 오디오 브리지 | 이번 장면과 관련 없었음 | 본 파이프라인에 오디오 트랙이 없음 (시나리오도 사운드는 별도 편집으로 분리) |
| T-08 Never-Render | 알고 있었지만 제작 중 고려하지 않음 | C08의 3중 협응이 렌더 불가 영역인지 판정하지 않음 |
| T-37 상태 전이는 화면 밖에서 | **시나리오 경유로 간접 적용** | DB를 직접 조회하진 않았으나 v2 시나리오의 C10(천 상태 전이)이 T-37을 내장했고, 그대로 촬영함 |
| LH-001 제작 교훈 | **기억에 의존해 부분 적용** | 적용: 마스터 스틸 우선, 뒷모습/손 클로즈업 신원 전략, C08 우선 시험. 미적용: v2가 명시한 사전 자료 조사 |

**핵심 발견:** 방법론은 시나리오 문서(v2) 안에 내장된 형태로만 작동했고,
제작자는 DB를 직접 펼치지 않았다. "문서가 기억을 대신했다" —
이것이 이번 제작의 실제 방법론 활용 경로다. 문제는 v2에 **없는**
지침(화면비 관리, 동작 검수 방법)은 어디에서도 작동하지 않았다는 점이다.

| 문제 | 최초 원인 단계 | 이후 수정 가능했던 단계 |
|---|---|---|
| A. 화면비 혼재 | ④ 프롬프트 작성 (비율 미지정) | ⑥ 검수 (치수 미확인), ⑦ 편집 (정규화 미실시) |
| B. 마을 미술 | ① 자료 조사 (미수행) | 없음 — 비교 기준이 없어 검수 불가 |
| C. 우물 동작 | ③ 연출기법 선택 (선례 의존, T-02 미검토) | ⑥ 검수 (신원만 보고 메커니즘 미검사) |
| D. 베틀 동작 | ① 자료 조사 + ③ 연출기법 선택 (복합) | ⑥ 검수 (키프레임은 동작을 평가 불가 — 구조적 한계) |

공통 패턴: **①→③ 구간의 판단이 선례(LH-001 1회 성공)에 의존**했고,
**⑥ 검수는 정지 화면 기준으로만 동작**했다. 움직이는 결과물을
정지 기준으로 검수한 것이 D의 구조적 원인이다.

## 5. 개선 제안 (제안이므로 기존 지침은 수정하지 않음)

### 5.1 기존 방법론에 있었지만 활용하지 못한 지침

1. **v2 Test Plan의 "사전 자료 조사"**
   - 증거: v2에 명문화되어 있었으나 베틀·마을 모두 미수행 [확인됨]
   - 확신도: 높음 / 예상 효과: B·D의 ① 단계 실패 제거

2. **T-02 결과만 보여주기 (C04 적용)**
   - 증거: "물을 길었다"는 C05에 이미 존재하는 결과 [확인됨]
   - 확신도: 높음 / 예상 효과: 메커니즘 직접 렌더의 리스크 회피.
     단, "기계 운동" 자체가 볼거리인 비트(C08급)와의 구분 기준은 별도 필요 (5.2)

3. **4문항 renderability interrogation**
   - 증거: 스탠딩 지시로 존재하나 C04·C08에 적용 기록 없음 [확인됨]
   - 확신도: 중간 / 예상 효과: ③ 단계에서 T-02 vs 직접 렌더의 판단 근거 제공

### 5.2 지침은 있었지만 선택 기준이 모호했던 부분

4. **"직접 렌더 vs T-02"의 선택 기준**
   - 현황: LH-001 C07(크랭크)은 직접 렌더 성공, VW-001 C04는 어색.
     선례만으로는 구분 불가 [확인됨]
   - 제안 후보: 동작의 **협응 자유도**로 판정 — 단일 주체·단일 축 회전
     (크랭크 돌리기)은 직접 렌더 후보, 다지 협응·인과 사슬(로프 감김→상승,
     발+손+북)은 T-02/인서트 후보. **가설이므로 재검증 필요** (5.5)

### 5.3 방법론에 없어서 새로 추가할 가치가 있는 판단 기준

5. **영상 프롬프트 필수 파라미터: 화면비·길이**
   - 증거: 13회 프롬프트 모두 미지정 → 3종 혼재·길이 불일치 3건 [확인됨]
   - 확신도: 높음 / 예상 효과: A 문제의 ④ 단계 원천 차단.
     단, 모델이 파라미터를 준수한다는 보장은 없으므로 ⑥·⑦의 확인 절차와 세트

6. **조립 전 규격 정규화 체크리스트**
   - 증거: `-c copy` 직결이 혼재를 최종물에 고착 [확인됨]
   - 확신도: 높음 / 예상 효과: A 문제의 ⑦ 단계 방어선.
     제안: 조립 전 전 클립 `ffprobe` → 16:9·통일 길이 강제 (크롭/패딩/속도 조정)

7. **동작 검수 방법 (Motion QC)**
   - 증거: 키프레임 2장 검수로는 C08의 동작 부자연을 잡을 수 없었음 [확인됨]
   - 확신도: 높음 / 예상 효과: D 문제의 ⑥ 단계 구조적 한계 해소.
     제안 후보: 기계·신체 동작 비트는 클립 전체를 2배속으로 시청,
     또는 1fps 덴스 프레임으로 동작 궤적 확인. **절차 가설이므로 효과 미검증**

### 5.4 생성 모델 자체의 한계로 추정되는 부분

8. **화면비·길이 지시의 낮은 준수율**
   - 증거: 스틸 "16:9" 지정에도 3:2 출력 1건, 영상 길이 텍스트 지정 3건 무시 [확인됨]
   - 단서: 모델명·설정이 기록에 없어 모델 귀인 불가. "이번 파이프라인의 관찰"로 한정
   - 확신도: 중간 / 대응: 프롬프트 지시 + 후처리 강제(5.3-6)의 이중화

9. **다지 협응 동작의 불안정성** (5.2-4와 연결)
   - 증거: C08 단일 사례 [확인됨 1건]
   - 확신도: 낮음 (n=1) / 대응: 5.5의 재검증 가설로만 유지

### 5.5 다음 제작에서 재검증할 가설

- H1: 얼굴 정면 합성 < 뒷모습/손 클로즈업의 신원 안정성
  (VW-001에서 1회 실패→1회 성공으로 관찰, n=2)
- H2: 단일 축 회전 동작은 직접 렌더 가능, 다지 협응은 인서트/T-02가 안전
  (LH-001 C07 성공 vs VW-001 C08 미흡, n=2 — 상충하므로 미결)
- H3: Motion QC(2배속 시청)가 키프레임 검수보다 동작 결함을 더 잡는다
  (절차 가설, 미검증)
- H4: 미세 동작 회피 가설 (v2에서 가설로 격하됨 — 통제 테스트 필요)

## 7. 한 줄 요약

이번 제작의 실패는 모델의 실패가 아니라 **절차의 실패**다:
조사하지 않았고(①), DB를 펼치지 않았고(③), 화면비를 적지 않았고(④),
움직임을 보지 않았고(⑥), 규격을 맞추지 않았다(⑦).
성공한 부분은 전부 "이전에 문서화된 것을 지킨 부분"이었다.
